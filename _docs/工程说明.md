# 知遇 · AI 深度婚恋匹配（小程序版）

原生微信小程序，无 npm、无云服务、无第三方 UI 库。全部数据存本机 `wx.setStorageSync`，不联网、不上传。

> **一句话定位**：能跑通完整产品流程、可演示、可评审的**原型**，不是能上线的产品。
> 差在哪、为什么差，见第五节「边界」。

## 一、怎么跑起来

1. 微信开发者工具 → 导入项目 → 目录选本目录（含 `app.json` 的这一层）。
2. **appid 必须填你自己的**（`project.config.json` 里已填入维护者的 `wxaf8dcd36953025b8`；换人使用请改成自己的，或导入时直接填写。用 `touristappid` 开发者工具会拒绝打开，测试号也不接受插件）。
3. 编译后从登录页填资料 → 首页「开始遇见」走完：访谈 → 校准 → 画像 → 匹配 → 1v1 → 会员。

## 二、开启语音输入（可选，两步）

默认**不声明**插件，因为用测试号硬声明会直接编译失败。要用语音就按下面做：

1. 小程序后台 → 设置 → 第三方设置 → 插件管理 → 添加「微信同声传译」，AppID `wx069ba97219f66d99`。
2. 在 `app.json` 顶层加：

```json
"plugins": {
  "WechatSI": { "version": "0.3.5", "provider": "wx069ba97219f66d99" }
}
```

加完重新编译，点输入框左边的 🎤 即可边说边出字。没加插件时点麦克风会弹出开启指引，键盘输入不受影响。

## 四、算法口径（可复核）

- 硬条件（先过滤，不满足直接不进池）：城市相等、`|年龄差| ≤ 阈值`、学历 ≥ 要求、性别符合、**不在拉黑列表**。
- 软条件：五维向量（生活节奏 / 定居意愿 / 消费观念 / 生育意愿 / 家庭边界，各 0-100）
  1. 各自去均值（中心化）；
  2. 求皮尔逊相关系数 `r`；
  3. 映射 `sim = (r + 1) / 2`；
  4. `sim ≥ 0.70`（等价 `r ≥ 0.40`）才推送。

**为什么不用余弦相似度**：五维全是非负值，余弦结果天然集中在 0.8 以上，两个三观相反的人也能算出 0.78，几乎没有筛选力。实测对照：完全相反的向量余弦约 0.79，皮尔逊 `r = -1.00`、`sim = 0.0000`。

五维数值不是让用户填的：访谈时按关键词表（`utils/interview.js` 的 `LEX`）从原话里推断，再在校准页让用户拖滑块修正。

## 五、演示边界（重要，别当成已实现）

### 5.1 账号体系：只有壳，没有可信身份

| 事情 | 现状 |
|---|---|
| 登录 | 本地生成 `u_xxxxxx` 的 uid，写在本机存储里 |
| 手机号 | 只做 11 位格式校验，**不发短信、不做验证码核验** |
| 实名认证 | 无，代码里连占位接口都没有 |
| 人脸核身 | 无 |
| 婚况联网核实 | 无 |
| 会话 / token | 无（没有服务端，也就没有可信凭据） |
| 跨设备 | 不支持，换手机 = 换账号 |

登录页底部与「我的」页都把这段写明了，没有藏。

### 5.2 照片：本机文件，不是云存储

选图后用 `FileSystemManager.saveFile` 落成持久路径（不是 `tempFilePath`，那个重启就失效）。上限 6 张、单张 5MB。
清缓存 / 换设备 / 重装都会丢，没有审核、没有鉴权、没有防盗链。

### 5.3 治理：举报只是本地记一条

举报会写进 `reports` 并**自动拉黑**（同时解除 1v1）。但：

- 没有后台受理队列，没有人工处理，没有处置回执；
- 没有证据留存（截图/聊天记录导出）；
- 真实产品这一套必须接审核后台 + SLA + 合规的证据留存。

### 5.4 AI：是规则引擎，不是大模型

访谈追问、对方回复、军师建议三处全部是 `utils/advice.js` 里的 if-else。
`utils/ai.js` 已经把所有调用收敛成一个 `ask(kind, payload)` 的 Promise 出口，**接真模型只改这一个文件**，页面零改动。

为什么现在没接：无密钥调用大模型必须走云端代理（前端不能放长期 key），而本项目的云服务开通在确认框里被拒绝了，见 5.6。

### 5.5 其他模拟项

| 能力 | 现状 |
|---|---|
| ¥2000 保结婚会员 | 点「模拟开通」只写本机记录，不发起支付、不接托管 |
| 24 位候选人 | 全部虚构，不含任何真实个人信息 |
| 1v1 对方回复 | 本地规则生成，不是真人也不是模型 |
| 实名 / 人脸 / 婚况 | 无 |

真实上线还需要：企业主体营业执照、婚恋交友类目资质（个人主体做不了）、腾讯云/阿里云人脸核身、官方婚况数据源、银行托管协议、内容审核。

### 5.6 云服务为什么没接（决策记录）

本次开发曾发起云服务开通（用于真登录 + 云数据库 + 云存储 + 免密钥 LLM），确认框返回 `declinedByUser: true`，随后按用户选择走本地版。所以：

- **真登录、跨设备、云照片、真 AI 四项全部未实现**，不是做完没测；
- 想升级，需要重新发起开通并在确认框点「同意」，然后按 `utils/ai.js` 顶部注释的三步改造；
- 云服务一旦开通，`store.js` 的本地存储要整体迁到 `cloud.database`，这不是改几行的事，是数据层重写。
