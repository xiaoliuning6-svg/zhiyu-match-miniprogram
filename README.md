# 知遇 · AI 深度婚恋匹配（微信小程序 · 原型）

一个原生微信小程序，用「AI 红娘深度访谈 → 结构化画像 → 相关性匹配 → 强制 1v1」跑通严肃婚恋的完整产品流程。

**定位：可演示、可评审、可继续开发的原型，不是能上线的产品。** 差在哪、为什么差，见文末「边界」——那部分请务必读完再看功能清单。

- 无 npm、无云服务、无第三方 UI 库，纯原生小程序
- 全部数据存本机 `wx.setStorageSync`，不联网、不上传、不收集真实隐私
- 24 位候选人全部虚构，不涉及任何真实个人信息

---

## 一、它跑的是什么流程

```
登录 → AI 红娘访谈（5 维 × 2 轮）→ 画像校准 → 画像卡 → 匹配结果 → 强制 1v1 → 保结婚会员
```

和「填表 + 无限滑卡」相反，这里的核心假设是：**先让人把话说清楚，再让他只认真对一个人。**

---

## 二、三个关键设计（不是随便写的）

### 1. 匹配用皮尔逊相关，不用余弦相似度

五维向量（生活节奏 / 定居意愿 / 消费观念 / 生育意愿 / 家庭边界，各 0-100）全是非负值，余弦结果天然挤在 0.8 以上——实测**两个三观完全相反的人，余弦也能算出 0.79**，等于没筛。

改成：

```
① 各自去均值（中心化）
② 求皮尔逊相关系数 r
③ 映射 sim = (r + 1) / 2
④ sim ≥ 0.70（等价 r ≥ 0.40）才推送
```

对照实测：完全相反的向量 `r = -1.0000`、`sim = 0.0000`；典型画像命中 6 人，区间 70%–97%。

### 2. 五维不让用户填

填表拿到的是"我希望自己是什么样的"，不是"我实际是什么样的"。所以访谈时按关键词表（`utils/interview.js` 的 `LEX`）从原话里推断——说"想买房、不回老家"，定居意愿直接给 95——再在校准页用滑块让用户修正。

### 3. 硬条件先过滤，软条件才算分

城市相等、`|年龄差| ≤ 阈值`、学历 ≥ 要求、性别符合、不在拉黑列表——任意一条不满足，直接不进候选池，不参与打分。这样"算出来 85% 但城市不对"的荒谬结果不会出现。

## 四、怎么跑

1. 微信开发者工具 → 导入项目 → 目录选**本仓库根目录**（含 `app.json` 的那一层）。
2. `project.config.json` 里已填了维护者的 appid；**别人使用请改成自己的**，或者直接在导入时填。
3. 编译 → 从登录页填资料 → 首页「开始遇见」走完流程。

### 语音输入（可选，两步）

默认**不声明**插件——用测试号硬声明插件会直接编译失败。要用语音：

1. 小程序后台 → 设置 → 第三方设置 → 插件管理 → 添加「微信同声传译」，AppID `wx069ba97219f66d99`
2. 在 `app.json` 顶层加：

```json
"plugins": {
  "WechatSI": { "version": "0.3.5", "provider": "wx069ba97219f66d99" }
}
```

重新编译后，点输入框左边的 🎤 即可边说边出字。没加插件时点麦克风会弹开启指引，键盘输入完全不受影响。

### 白屏排查（踩过的坑）

首次导入或改过 `app.json` 后如果整屏空白、只剩导航栏，先按 **Ctrl+B** 全量编译；仍白就 **清缓存 → 清除全部缓存并重新编译**。原因是编译快照没包含新加的页面，而首屏会立刻 `reLaunch` 过去，路由被打断。

入口页的跳转已统一延后一帧（`setTimeout 60ms`），避免打断尚未完成的 `appLaunch`。

## 六、边界（重要，别当成已实现）

### 账号体系只有壳

登录是在本机生成一个 `u_xxxxxx` 的 uid 存进本地存储。手机号只做 11 位格式校验，**不发短信、不验验证码**；没有服务端，也就没有 token / session / openid；换设备等于换账号。实名认证、人脸核身、婚况联网核实——**代码里连占位接口都没有**。

### 照片是本机文件，不是云存储

选图后 `saveFile` 落持久路径（不用 `tempFilePath`，那个重启就失效），上限 6 张 / 单张 5MB。清缓存、换设备、重装都会丢。没有审核、没有鉴权、没有防盗链。

### 举报只是本地记一条

会写进 `reports` 并自动拉黑、自动解除 1v1。但没有后台受理队列、没有人工处理、没有处置回执、没有证据留存。

### AI 是规则引擎，不是大模型

访谈追问、对方回复、军师建议三处全是 `utils/advice.js` 里的 if-else。`utils/ai.js` 已把所有调用收敛成一个 `ask(kind, payload)` 的 Promise 出口，**接真模型只改这一个文件，页面零改动**。

### 会员与候选人

¥2000 保结婚会员点「模拟开通」只写本机记录，不发起支付、不接资金托管。24 位候选人全部虚构，1v1 里"对方回复"由本地规则生成。

### 真上线还缺什么

企业主体营业执照、婚恋交友类目资质（**个人主体发布不了这个类目**）、人脸核身、官方婚况数据源、银行资金托管协议、内容审核与举报处置后台、隐私政策与用户协议。缺一条都过不了审核。
